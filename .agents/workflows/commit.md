# Workflow: Commit (Optional)

A lightweight convenience workflow, outside the memory lifecycle. Use it when the user asks you to commit.

1. Read all **staged** changes (`git diff --cached`) to understand what was worked on.
2. Create a single commit from the terminal whose message clearly explains **what** was done and **why**.

> Adapt the message convention to your project (e.g., Conventional Commits). This workflow does not stage files for you — review what is staged first.
